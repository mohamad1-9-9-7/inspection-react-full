# 👥 وحدة القوى العاملة — Workforce

وحدة **مستقلّة بالكامل** عن وحدة الجزار الشغّالة. كرت جديد داخل «المخزون» → `/workforce`.

## ليش منفصلة

- نوع سجل خاص فيها: `workforce_config` — **لا يلمس** `butcher_config`.
- ولا سطر تعديل على `ButcherLog` / `ButcherView` / `ButcherSupervisor` / `ButcherMyWork`.
- منقدر نضبّط السياسة كاملة ونجرّبها، وبعدين منوصلها بشاشة التسجيل لما ترتاح إلها.

## الملفات

| الملف | الدور |
|---|---|
| `workforceConfig.js` | النموذج والتخزين والإجراءات النقيّة (نقل، حالة، تحقّق) |
| `workforceScope.js` | **الملف الوحيد** اللي بيقرّر مين يشوف شو + بوابة الكشك `checkEntry()` |
| `WorkforceHub.jsx` | الشاشة الرئيسية: مؤشّرات + تبويبات |
| `WorkforcePeople.jsx` | شجرة: ملحمة ← مشرفوها بصف واحد ← جزارو كل مشرف · منتقي الموظفين · نقل · إيقاف · حذف |
| `WorkforceSites.jsx` | الملاحم — أي فرع فيه تقطيع |
| `WorkforceGate.jsx` | محاكي البوابة — جرّب أي رقم وشوف القرار وسببو |
| `WorkforceLog.jsx` | سجل الحركة (غير قابل للتعديل عمداً) |
| `WorkforceRules.jsx` | كل القواعد، مع شرح تحت كل وحدة |
| `WorkforceAccountLink.jsx` | ربط الموظف بحساب دخول موجود (بحث، لا كتابة) |
| `workforceAccounts.js` | قراءة حسابات الدخول من `/api/app-users` |
| `workforceUi.jsx` | ذرّات الواجهة المشتركة |

## النموذج

```
site   = فرع من inspectionBranches معلَّم إنه ملحمة تقطيع (ما منبني قائمة فروع ثانية)
person = { id ثابت, empNo, name, role, site, supervisorId,
           username, accountName,      ← حساب الدخول المربوط
           status, effectiveFrom, history[] }
```

- `id` منفصل عن `empNo` عمداً: الأرقام الوظيفية بتتكرّر وبتنكتب غلط، الـ `id` لأ — فتاريخ الموظف بيضل سليم.
- **جزار** = ملحمة وحدة + مشرف واحد. **مشرف** = ملحمة أو أكثر.
- `username` = حساب الدخول المربوط، **اختياري** للاثنين ولكل الأدوار.
- **عدد المشرفين للملحمة مفتوح.** بتبويب الموظفين بيظهروا كلهم بصف واحد تحت
  «مشرفو هذه الملحمة»، كل واحد برقم (①②③) ولون ثابت، ونفس الرقم واللون
  بيتكرّروا فوق مجموعة جزارينه تحت — الرقم واللون هنّ الرابط البصري.

## البوابات الست (`checkEntry`)

| # | البوابة | بترجع |
|---|---|---|
| ① | الهوية — رقم غير مسجّل | `unknown` |
| ② | الحالة — موقوف / مغادر | `suspended` · `left` |
| ③ | الدور — المشرف ما بيسجّل تقطيع | `role` |
| ④ | الـ PIN | `pin_required` · `pin_wrong` |
| ⑤ | **الموقع** — الموظف بلا ملحمة | `no_site` |
| ⑥ | تاريخ سريان النقل | `not_yet` |

النجاح بيرجّع الملحمة **مقفولة** (`locked: true`) — بلا قائمة مفتوحة.

## النقل

`transferPerson()` ما بتلمس السجلات القديمة إطلاقاً. كل سجل تقطيع بيحمل ملحمته وقت
التنفيذ، فتقارير التصافي التاريخية بتضل صحيحة بعد أي نقل. النقل بيتطلّب **سبب**
وبينكتب بالـ `history` مع مين عملو وإيمتى.

## الصلاحيات

**الصفحة عادية ومفتوحة** — مين ما فتحها بيشوف كل الملاحم وبيقدر يضيف وينقل ويعدّل.
ما في تقييد أدمن ولا نطاق ملاحم؛ الكرت بيظهر لكل من بيوصل لصفحة المخزون.

`useWorkforceScope()` بـ`workforceScope.js` هو المكان **الوحيد** اللي بيرجّع
الصلاحيات (كلها `true` حالياً). لو رجعنا يوماً بدنا نضيّق، منغيّرو هون بس —
ما في شرط صلاحية مكتوب جوّا الشاشات.

⚠️ بوابة الكشك (`checkEntry`) شي تاني: بتفحص الرقم الوظيفي وحالة الموظف
وملحمته **وقت تسجيل التقطيع** — ما إلها علاقة بمين بيفتح هالصفحة.

## ⚠️ ما بعد

الخطوات الباقية لوصل الوحدة بشاشة التسجيل:

1. ~~تعريف الجزار بشاشة التسجيل~~ — **صار**: `accountIdentity()` بتعطي
   `ButcherLog` اسمه ورقمه وملحمته من حسابه، وبتقفلهم (انظر «حساب الدخول» تحت).
   الباقي من `checkEntry()` (رفض غير المسجّل + الـPIN) لسّا ما انركّب.
2. ختم `personId` / `supervisorId` / `site` بكل سجل تقطيع.
3. ~~حصر لوحة المشرف~~ — **صار**: اللوحة بتفلتر على `identity.sites` مباشرة
   (مش عبر `filterRowsByScope`)، فالمشرف بيشوف سجلات ملاحمه وبس. باقي شاشات
   التقارير لسّا مفتوحة.
4. **فرض على السيرفر**: رفض 403 لو الملحمة مش تبع المستخدم — يبني على طبقة
   التوكن الموجودة (`REQUIRE_AUTH`) بمستودع `D:\inspection-server`.

## حساب الدخول

قسمة المسؤوليات، وهي المبدأ اللي بينى عليه كل شي هون:

| مين بيقرّر شو | الشاشة |
|---|---|
| مين بيقدر يسجّل دخول (اسم مستخدم · كلمة سر · صلاحيات) | مركز إضافة الحسابات |
| **مين هوّ** هالحساب — رقمه الوظيفي وملحمته ومشرفه | القوى العاملة (هون) |

فما في خانة «رقم وظيفي» بمركز الحسابات ولا لازم تكون: الربط بينعمل من هون،
بخطوة ③ «حساب الدخول» بمحرّر الموظف. **اسم المستخدم ما بينكتب بالإيد أبداً** —
بتبحث بالحسابات الموجودة فعلاً (`/api/app-users`) وبتختار واحد. اسم مكتوب غلط
بيعني موظف ما بيتعرّف عليه النظام وقت الدخول وما في شي بالشاشة بيكشف الغلطة.

الحساب المربوط بجزار **نشط** بيخلّي `ButcherLog` تعرفه فوراً: بدل خانة الرقم
والقائمة المنسدلة بتطلع بطاقة مقفولة (اسم · رقم وظيفي · ملحمة)، وبتضل شارته
ظاهرة وهو عم يسجّل الأوزان. الحساب غير المربوط بيشوف الشاشة القديمة حرفياً،
فالكشك المشترك ما بينكسر.

الحسابات المربوطة بموظف آخر بتظهر بالبحث **معلّمة باسم صاحبها** لا محذوفة —
نفس قاعدة سجل الموظفين. واسم مستخدم محفوظ ما عاد إله حساب بيظهر بعلامة ⚠️
صريحة، ما بينمسح بصمت.

## سجل الموظفين

الرقم الوظيفي **ما بينكتب بالإيد**. بينتقى من `DIRECTORY` بـ`workforceConfig.js`،
وهي مبنية من `EMPLOYEES` (`src/pages/ohc/OHCUpload.jsx`) — **نفس السجل** اللي بتقرأ منه
شاشة تسجيل الجزار. الاختيار بيملّي **الرقم والاسم وبس**.

⚠️ حقلا **الفرع والمسمّى الوظيفي** بذاك السجل قديمان وما بينتحدّثوا مع كل نقل، فما
منعرضهم ولا منبحث فيهم ولا منبني عليهم اقتراح ملحمة — اقتراح مبني على فرع قديم
بيحطّ الموظف بملحمة غلط. الملحمة بتنختار يدوياً بالخطوة ② وهي مصدر الحقيقة.

الأرقام المضافة مسبقاً بتظهر بالقائمة **معلّمة «مضاف مسبقاً»** لا محذوفة — حتى يعرف
المستخدم إنه لقى الشخص الصحيح. والسجلات القديمة اللي انحفظت برقم يدوي بتضل قابلة
للتعديل (التحقّق الصارم على الإضافة الجديدة بس).
